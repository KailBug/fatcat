### 共同交付门槛

- 所有资料访问绑定本次实际执行的 Session 及其有效作用域，包括子任务和自动任务；同目录不自动共享，UI 当前选择不决定后台任务权限。原件、解析结果、索引、历史和 Memory 分别有明确所有者。
- harness 落实作用域、权限、能力及预算，模型依任务选择文件、页、查询和后续展开。用户可用自然语言指定“完整阅读”“只看第几页”“在项目资料中查找”，无需为每个任务选择 RAG 开关；文件大小只是考虑因素之一。
- 界面与回答展示实际使用的资料、定位和未覆盖范围。完整阅读、全文总结、全面审查遇到预算或解析限制时报告不足并分批继续/请求缩小范围，不能用少量命中片段冒充全文覆盖。
- 所有外部识别、Embedding 及原生文件请求均有次数/批量/时限/输入输出预算、取消、安全错误及用量记录，凭据不进入快照。索引可重建，历史引用固定内容与解析版本，版本变化不使旧引用指向新内容。
- 每阶段先用临时夹具、假凭据与注入传输验证，再按该阶段需要独立记录 Windows 实际解析/界面结果和经授权的真实服务质量。完成实现后运行仓库相应 `pnpm` 检查；阶段 3 新增经夹具验证的本地解析依赖，不添加尚不可用的配置；真实界面测试不等于真实模型质量验证。

### 阶段 1：Project 与 Session 关联

**已确认最小范围**：Project 是显式组织实体，保存身份、名称、项目工作目录和持久化修订；Session 保存归属，项目不汇总所有会话历史。创建项目、项目内创建多个 Session、列出/恢复归属，以及将空闲独立 Session 加入项目，形成首个可用闭环。项目内新会话必须使用项目工作目录，不提供会话级覆盖；项目之外访问继续受现有权限控制。同目录的独立 Session 不会自动加入项目。

迁入先展示资料共享范围；目录不同时展示旧路径和项目路径并取得用户确认。成功后只改变后续执行目录与资料归属，不搬移/复制原目录文件，不改写历史消息和来源路径。保存目录变化事实并在下一轮请求中告知模型，使旧目录的审批失效。运行中或待审批的会话必须先结束/取消当前操作；HTTP/UI 和共享核心都要拒绝绕过。阶段 1 尚无附件，迁入资料共享提示先建立产品契约，阶段 2 才验收实际资料转换。

**已实现边界**：`src/project/` 负责项目记录、校验、持久化与具体迁入记录转换；Session record/store/manager 和 AgentSession 接入归属、目录解析、持久执行领取及请求侧变更通知。Session v2 使用互斥的 `location = standalone(workspace) | project(projectId)`，由 Project 唯一持有项目工作目录；`storageWorkspace` 仍表示原存储桶，不按项目搬迁快照。旧 v1 可只读为独立 Session，首次成功持久写入升级，保留历史/compaction/fork/未完成回合；旧程序拒绝 v2，升级前需停止旧实例，不支持新旧版本并发写入。CLI/chat/TUI/Web UI 共用管理边界；Web UI 提供项目创建/分组、新建、拖入/菜单与路径确认，CLI 提供 `--project` 和共享 `/project` 命令。具体模块与验证见 [PROJECTS.md](ARCHITECTURE/PROJECTS.md)，无新框架或未来系统占位。

**当前最小范围**：阶段 1 最初固定项目目录并禁止删除；阶段 2 后用户追加的管理增量现已开放项目重命名、确认统一改目录与确认级联删除。删除成员会话/任务和项目资料，但保留其他会话仍引用的原件，永不删除工作目录文件。解除关联和跨项目迁移仍未开放。项目内 fork 保留归属、独立复制历史且不复制自动任务。迁入和项目改目录原子暂停自动任务，旧归属代次的激活失效，审阅后可恢复任务。保留现有按 workspace 发现任务的范围；后台与子任务绑定真正执行的 Session，不能使用 UI 当前选择或目录缓存作为范围。附件共享已在阶段 2 实现，Memory 尚未实现。

### 阶段 2：持久文件与共享读取

**已实现，验收事实见 PROGRESS**：原件/catalog/关联/pin 由 `src/attachments/` 持有，Session 历史另存；`read` 包装复用既有工具并绑定实际父子执行 Session。Web UI 有上传/清单/分页/版本来源/下载，CLI/TUI 有本地命令；均有项目共享、私有隔离和独立移除/销毁行为。单文件 16 MiB；只有 `.txt/.md/.markdown` 可读，其他允许格式只保存，不声称解析成功。浏览草稿不保存空历史，成功上传才保存草稿。无持久化模式仅保留进程内原件。具体限额、故障/残留与兼容说明见 [ATTACHMENTS.md](ARCHITECTURE/ATTACHMENTS.md)。

**最小范围**：Web UI 有界上传与 CLI/TUI 共用的本地导入核心，独立保存不可变原件、稳定身份/版本和项目或会话关联，提供清单、状态、基本读取与来源引用。先以 UTF-8 文本/Markdown 验证内容读取；其他允许上传的格式明确显示“待解析/尚不支持分析”，原件保存不等于解析成功。项目内上传默认项目所有，上传者 Session 仅为来源。

上传绑定发起时的目标 Session、目标作用域及关联版本，不在完成时读取 UI 当前选择；若目标已被删除或迁移，拒绝发布，用户在新范围重新选择文件，不能静默改归属。首次接受持久附件即保存 Web UI 草稿；仅内存 Session 的导入保持临时并在退出时清理。本地路径导入仍经过当前文件访问权限，不能把附件导入变成越界读取旁路。

带附件的独立 Session 迁入时，私有关联持久晋升为 Project 所有，与 Session 归属共同写入恢复日志；所有 Session/附件读写先恢复已决定的提交。不能在读取时沿 `uploaderSessionId → projectId` 动态推导所有权；上传者删除后项目关联仍存在。已补元数据总锁、资料范围修订/指纹、幂等 uploadId 和每次传输的 stageToken；故障、真实第二进程中断与上传旧清理验收见 PROGRESS。

“移除关联”使资料退出该作用域并撤销当前读取；“永久删除”销毁原件，当前尚无派生物，确认后可一并移除本作用域关联。其他有效关联或任何 retained pin 存在时明确拒绝销毁。旧回答保留引用身份与版本；pin 只保留字节，不绕过当前作用域。暂不自动垃圾回收，删除最后一个私有 Session 后可能保留孤立原件；在删除 Session 前管理可销毁原件。

### 阶段 3：文档解析与视觉理解

**2026-10-14 实现与验收状态**：已实现现代格式本地解析、PNG/JPEG 与选定 PDF 页的同模型视觉/转写适配、固定解析版本缓存、通用读取/字面搜索、来源及覆盖 UI。本地夹具、注入 API 和真实 Edge 闭环已执行，最终结果以 PROGRESS 为准；没有真实视觉 API 请求，识别质量尚未验收。详细矩阵及限制见 [DOCUMENTS.md](ARCHITECTURE/DOCUMENTS.md)。原生 PDF/Office API 输入当前明确不可用，不以图片能力假装原生文件能力；独立 OCR、旧 Office、Office 图表渲染及公式重算未实现。以下验收条件继续作为阶段边界，不将软件合约测试等同于业务材料质量验收。

**最小范围与推荐格式**：逐项支持 Markdown、文本 PDF、现代 Word `.docx`、Excel `.xlsx`、PPT `.pptx`，再交付图片与扫描 PDF 的识别路径；建议图片先验证 PNG/JPEG。旧 `.doc/.xls/.ppt`、宏文件、加密文档及更多图片类型单列支持矩阵，未验证前明确不支持，不能笼统写成“Office 全支持”。本轮采用现代格式最小范围，旧格式明确要求转换；如后续确有旧格式需求再扩展。

统一解析产物供通用读取与搜索复用，不每格式增加模型工具。保留页、标题、段落、工作表/单元格、幻灯片及对应版本；原生提取文本、OCR/模型转写和模型描述分别标注。支持原生文件的模型/API 可以在任务适合、范围和预算允许时直接接收文件；原生文本与结构优先本地解析，精确定位和表格处理仍按所需结构读取。按任务、类型、材料规模、上下文、能力与解析状态选择路径，不仅按大小。

**2026-10-14 已确认设计，当前实现范围见上文**：图片、扫描页和图表优先复用当前聊天模型的多模态能力，前提是具体模型、供应商 API 和 Fatcat 消息适配均已验证。直接看图分析不要求先全文 OCR；需要可搜索文字、可复用转写或文字核对时，按任务生成并缓存带来源的文字提取结果。独立视觉/OCR 服务只在现有能力不足或代表性样例证明质量、定位、成本或延迟存在缺口时接入，届时才增加独立配置；不要求用户预先购买服务，不提前增加无用配置或插件接口。模型仅支持图片不等于支持 PDF 原件输入，必要时有界渲染选定页面。解析或识别失败不能伪装成空资料。

| S3-02 | 未配置独立 OCR 服务时，以已适配多模态模型和仅文本模型分别读取扫描 PDF、文字图片及图表页 | 前者可使用获准页面进行视觉分析，不强制先 OCR；后者在无可用识别路径时明确原因和未覆盖页。若另行实现可选识别服务，再验证该路径；失败不生成假空文档 |

阶段 3 可在没有独立 OCR 服务、向量库、Embedding 凭据或 Memory 的情况下交付并验收。图像分析仍需要一条实际可用并经过验收的视觉路径；仅能报告不支持不等于已经交付视觉理解。先验收本地解析和多模态内容适配，再按任务需要验收可复用文字提取；不必同时接入专用 OCR。

### 阶段 4：最小跨会话 Memory

**已确认最小范围**：“跨会话记忆”与 Memory 为同一个系统；进入实现阶段时，在 `src/memory/` 建立独立模块。只处理用户明确要求记住的决定、偏好和约定，提供查看、修改、删除、修订及来源。项目决定归项目，独立会话信息私有；只有用户明确指定的全局偏好跨项目使用。原件、历史和提炼记忆分别管理。

推荐首版使用有界、可枚举的记录按作用域和任务加载，不依赖向量化；自动提炼、自动合并和自动冲突解决留后续。Memory 内容不是权限授权或系统规则，工具约束仍由既有配置/权限执行。读取历史中的旧记忆引用不应使已修改或删除的条目重新生效；无法抹去旧对话中已写入的内容时，应明确当前有效修订与删除状态。

独立 Session 迁入 Project 时，用户已确认自动共享的是上传资料，不能据此推断私有 Memory 也应共享。推荐既有私有记忆仍绑定该 Session，其他项目会话不可读取；如用户选择把条目转为项目记忆，再显式发布并保存来源。该迁入策略属于待确认产品问题，须在阶段 4 提供此路径前确定。

| --- | --- | --- |
| S4-01 | A 明确要求记住项目决定；P 内 B 在相关任务中询问，项目 Q/独立 C 再询问 | P 内可使用并追溯 A 的来源；其他作用域不加载该条目，任务不需 RAG 即可完成 |

| S4-03 | 查看、修改和删除条目后继续已有会话并新建会话 | 后续请求使用最新有效版本/删除状态，不把旧历史中的记忆当当前事实；来源与修改记录可核对 |
| S4-04 | 模型作出未确认推断，或记忆中包含扩大权限的约定 | 未确认推断不自动写入长期记忆；约定不能改变权限上限或跳过审批 |

### 阶段 5：文本 RAG 检索层

**最小范围**：在已成功解析、可定位的文本上加入关键词、独立在线 Embedding、混合检索和排序，返回有界证据并支持展开原文。索引记录原件/解析版本、模型标识、维度及配置，用于失效判断与重建；不与原件、Session 历史或 Memory 混存为同一种事实。数据库、分块大小/重叠、中文关键词策略及排序权重经代表性资料比较后选择，不预绑定大型框架。

原生文本直接复用本地解析；扫描页进入文本索引时需要文字提取，可使用阶段 3 的多模态转写，不要求独立 OCR 服务。只有描述、摘要或部分转写的页面必须标明索引覆盖，不能视作已收录全部文字。聊天模型能看图不代表文本 Embedding 能接收图像；直接图片/页面检索属于阶段 7 的候选方案，可提前用代表性查询比较，但不预先改变本阶段的文本基线。

先建立固定中文问题、精确术语/编号和已知证据集合，比较关键词、向量及混合方案的召回、来源正确性、读取覆盖、请求量与延迟，再冻结该增量的质量门槛；不能凭少量演示决定参数。模型先检索定位、再展开章节/页是正常路径。未建索引、部分索引或无结果应可见，已有直接读取不能被 Embedding 不可用阻断。

| --- | --- | --- |
| S5-01 | 用固定中文同义问法及精确编号查询带人工标注证据的资料 | 输出评测结果和未命中样例，返回来源定位正确；按事先冻结的门槛验收，不只展示最佳案例 |
| S5-02 | 同一查询分别在项目 P、项目 Q 和独立 Session 执行，并尝试伪造范围 | 候选生成、排序、读取均不能包含未获准资料；后台/子任务范围与所属执行一致 |
| S5-03 | 查询不存在的事实，或只完成部分资料索引 | 明确无结果/覆盖范围，不能据空召回声明整个项目没有该事实；可以选择原文读取继续核查 |
| S5-04 | 修改原件/解析版本，切换 Embedding 模型/维度后查询并重建 | 失效索引不混用，重建与旧引用分离；兼容配置记录可核对，失败重建不破坏原件或历史 |

### 阶段 7：多模态检索

**最小范围**：选择真实需求中的一种模态与固定查询集，比较 OCR/图片描述/转写的文本检索与必要时的专用多模态 Embedding；先证明现有文本派生路径的不足，再决定引入新服务。支持查到图、图表页或主题音频片段，并继续查看原始内容；保留与文本检索一致的作用域、版本、定位和有界结果。没有专用多模态模型时，明确当前实际使用的只是文本派生检索。

文字提取基线可以来自现有多模态模型，无需先部署专用 OCR。专用图片/页面 Embedding 可以形成不依赖 OCR 文本的检索路径，但必须验证对应检索模型和查询适配，不能拿聊天视觉能力替代。是否采用由代表性查询的命中、来源定位、成本与延迟决定，不假设专用 OCR 或多模态检索天然更优。

| 编号 | 输入与动作 | 可执行验收条件 |
