## 用户已确认的方向

- Project 是显式组织实体，持有项目工作目录；其成员 Session 必须使用项目目录，不能单独覆盖。同目录不等于同项目，目录外操作仍由现有权限控制。
- 项目内上传资料默认项目共享；独立 Session 的资料私有。各会话历史独立，上传者只记为来源，不能成为项目资料唯一生命周期所有者。
- 独立 Session 迁入项目后，后续操作使用项目目录，已有上传资料转为项目共享；必须提示共享变化，目录不同时展示并确认路径变化。运行中或待审批时不能迁入；不搬动原目录文件，不改写历史，记录变更并在下一轮告知模型，旧审批失效。
- 根据任务选择直接读取、原生文件输入、本地解析、视觉/OCR 或音频转写。本地解析优先；原生输入以实际 API/模型能力为准，精确定位与结构化处理仍需解析。附件分析不以向量化为前提。
- Harness 负责作用域、权限、能力及预算，模型选择文件、页、查询和后续读取；用户无需每次开关 RAG。自然语言指定的资料范围和阅读深度必须生效；全面总结或审查不能把少量召回片段冒充全文覆盖。
- 在线 Embedding 与聊天模型独立配置，音频识别保留独立配置方向。视觉理解与文字提取优先复用当前聊天模型已验证的多模态能力；确有需要才接入可独立配置的视觉/OCR 服务，不把它作为附件分析或文本 RAG 的必需服务。目标资料为 Markdown、PDF、Word、Excel、PPT、图片及后续音频；现代 Office 和旧格式的范围分别说明。
- “跨会话记忆”和 Memory 是同一系统，未来代码集中在 `src/memory/`。项目决定与约定留在项目，独立会话信息私有；只有用户明确指定的全局偏好跨项目。首版只做用户明确记住内容的查看、修改、删除及来源，不同时做自动提炼/合并/冲突解决。
- 原件、解析结果、索引、会话历史和 Memory 各自管理。Memory 不依赖 RAG，RAG 不必等待完整 Memory，音频分析可提前于文本检索。

### 多模态、OCR 与检索：公开依据及设计取舍

以下公开依据用于 2026-10-14 的设计澄清，不是 Fatcat 已实现能力或 Codex 内部架构证据：

- [Azure OCR skill](https://learn.microsoft.com/en-us/azure/search/cognitive-search-skill-ocr) 提供识别文本及带行/词位置的布局输出；[Google Document AI 的 Document 结构](https://docs.cloud.google.com/document-ai/docs/reference/rest/v1/Document) 定义文字锚点、页面布局、坐标及置信度。它们说明专用文档识别可以提供定位契约，不说明每个多模态模型都能提供同样字段，也不证明专用 OCR 必然更准确或便宜。
- [ColPali 论文](https://arxiv.org/abs/2407.01449) 展示基于页面图像表示的检索路线，可以不依赖 OCR 文本索引。这说明 OCR 不是所有 RAG 的必需组件；它需要相应检索模型，不能仅靠聊天模型支持图片来推导。Fatcat 未选定或接入该方案。

**设计推断与已确认取舍**：区分“从图像提取文字的任务”和“单独部署 OCR 服务”。多模态模型可以承担前者，所得转写同样可以缓存、进行关键词/文本向量检索、核对编号及比较扫描版本；识别错误仍需对照原页。专用 OCR 的价值由真实样例中的提取质量、定位、成本和延迟决定，首版不预设必须接入。视觉描述适合补充图表含义，但不等同于逐字转写或全部页面覆盖。

## 资料范围、迁移与生命周期

### 实际执行身份

每次回合捕获实际 Session、Project 或私有范围、归属代次及有效工作目录；后台任务使用任务绑定 Session，子任务继承或缩小父回合允许的范围。UI 选择、相同目录、文件 ID/哈希和模型传入的 projectId 都不是授权依据。读取、搜索、预览、下载以及检索结果展开要验证关联；索引筛选和返回证据时也应校验，不能只在界面隐藏别的项目。

`workspaceAgentFactory` 仍缓存同目录 Tools；`createAgent.forSession` 在激活时给父子模型绑定真实 Session/Project/归属代次/目录，后台目标不依赖浏览器选择。阶段 2 已在目录缓存之外装配附件 read，Store 执行时校验同一身份。目录缓存仅保留与资料范围无关的文件工具及执行记录。

项目目录是文件操作默认基准，不是新的权限授权。既有 read/write/shell/browser/web 继续执行当前权限与启动上限。资料接口的逻辑隔离也不是 OS 沙箱承诺：现有 shell 和 Free to go 的本地访问能力仍按现有规则说明。用户显式选文件导入只授权该导入，不泛化为任意目录访问；模型按路径导入仍走现有文件访问检查。

### 上传与归属发布

上传开始时绑定明确的 Session ID、目标 Project/私有范围、归属代次和上传 ID。切换 UI 不改变这些值；完成前目标被删、归属迁移或相关状态冲突时，拒绝发布并清理临时数据，不能自动改投当前 Session 或新项目。普通历史更新不必等同归属变化，应使用明确的归属代次，避免把正常追加消息误判为转移授权。

暂存、原件完成、关联可见是不同状态。先持久保存完整原件，再发布可见关联；失败或取消不能显示为 ready。发布失败的无关联原件可留作可识别的待清理数据，但不能产生悬空引用。建议显式完成添加附件时才把 Web UI 草稿持久化，仅选文件/取消不保存；无持久化独立会话使用临时资产并在结束后清理，不发布持久项目资料。

独立 Session 迁入时，阶段 2 已把私有上传关联持久晋升项目，与 Session 归属通过恢复日志一致发布，不依赖上传者当前 projectId 动态推导。确认绑定真实数量、资料修订/指纹和目标修订，资料变化后重新确认；故障与真实第二进程恢复事实见 PROGRESS。

删除上传者 Session 不移除项目资料。已实现项目 fork 继承项目、复制独立历史，原共享资料继续属于项目；独立 fork 复制全部有效私有关联与来源 pin，删除源 Session 不破坏 fork。移除关联撤销该范围读取，pin 只防销毁，不授权历史读者绕过当前范围。暂不实现孤立原件自动回收。

### 稳定引用与删除

来源引用固定原件内容版本、解析版本和页/段落/单元格等位置，不能只保存可变文件名或 chunk 序号。重新上传、修改原件、重做 OCR/解析后产生新版本；旧回答仍定位旧内容，无法保留时明确显示不可用，绝不悄悄指向新版。原生输入若只提供文件级证据，则展示文件级来源，不能虚构页码。

“移除关联”只将资料移出对应范围的发现/检索集合；“永久删除”才清除原件与派生内容。建议首版永久删除仅允许不存在其他活动关联及需保留的历史引用时进行；有依赖则拒绝并列明影响，不自动级联删除。以后如支持明确的强制清除，应保留不可用来源的墓碑记录。保留字节不等于保留访问权；解除关联后的历史可显示原引用和不可访问状态，但不能绕过当前作用域重读原件。删除原件也不会抹去已经写进历史的文本。

项目会话解除关联后不自动带走整个项目的资料或 Memory。解除与跨项目迁移仍未开放，产品决策见 [PROJECTS.md](PROJECTS.md#5-操作行为与真正待定的产品问题)。用户追加确认的项目删除已独立实现：删除成员会话与项目资料，保留外部引用原件，不删除工作目录文件；这不代表未来 Memory 的删除已经实现。

## 内容获取与上下文选择

选择依据是任务目标、文件类型、材料规模、可用上下文、解析状态和模型能力，不能仅按文件大小分流。Harness 提供有界清单、可用方式和约束，模型选择内容与后续工具调用；用户自然语言要求的范围和深度优先于默认启发式，但不能突破权限或硬预算。

| 任务 | 默认组合建议 | 必须报告的边界 |
| --- | --- | --- |
| 短文理解、指定页或章节 | 直接读取有界正文或原始页面，必要时按页展开 | 实际读取的文件/页/段落，截断与未读部分 |
| 完整阅读、全文总结、全面审查 | 建立页/节等覆盖单位，分段读取与汇总，保留跨段问题 | 处理进度、失败和未覆盖单位；预算不足时声明部分完成，不能用 top-k 冒充全文 |
| 大量材料中定位事实 | 先关键词/语义检索，再展开完整章节、表格或页面核对 | 查询范围、证据版本、无结果与遗漏可能 |
| 图片、扫描页、图表和布局 | 先检查本地可提取结构，再按任务复用已适配聊天视觉；独立视觉/OCR 为可选补充 | 原生提取文本、OCR/模型转写和模型描述分开；报告无法识别处，不伪造坐标或置信度 |
| Excel 汇总与计算 | 读取工作表/单元格结构，使用受控计算路径处理所需范围 | 原公式、缓存值与本次实际计算值区分；不能只靠片段召回或不明缓存回答合计 |
| 供应商支持原生文件输入 | 按已验证 API/模型能力发送指定版本，必要时辅以本地定位 | 发送文件不等于证明已完整处理；缺少结构/定位时继续解析或明确局限 |
| 会议录音及指定音频段 | 转写或经过能力验证的音频理解，按时间分段核对 | 缺失/失败片段、时间范围、说话人不确定性，以及转写与推断的差别 |

解析状态要区分 empty、unsupported、failed、partial 和 ready；有扫描图像但无文本层不能当作空白文件成功返回。解析器按原件/配置版本缓存，有取消、时间、解压大小、页数/单元格数和输出限制。通用 `read` 与搜索消费同一定位内容，检索层可晚于解析交付。对恶意/损坏文档的资源限制在解析边界实施，外来文档内容作为资料而非系统指令。

直接看图、分析图表或选定扫描页不要求预先全文转写。需要可搜索文字、逐字核对或跨会话复用时，再按任务生成文字提取产物；文本 RAG 只能索引实际获得的文本，不能把图片描述当作完整原文。支持图片不等于支持原始 PDF 输入，页面渲染与原生文件传输分别验证，不因模型名称或 SDK 类型自动宣称可用。

建议可复用转写保存原件版本、页/实际位置、处理方法、模型/配置版本、产物版本，以及成功、失败和未覆盖单位；原生提取、模型转写与模型解释保留不同来源类别。只有实际取得位置时才保存区域坐标，没有定位输出时使用页面级来源；没有置信度则不补造数值。缓存由派生内容模块持有，供通用读取与搜索共用，跨 Session 复用仍检查当前资料关联。重做提取产生新版本，旧回答引用不变；移除关联撤销读取，不能通过缓存绕过。该契约是阶段 3 的实施建议，不提前建立未使用的解析插件框架。

建议首批格式明确列为 `.md`、`.pdf`、`.docx`、`.xlsx`、`.pptx` 与经样例验收的图片格式；`.doc/.xls/.ppt` 首版明确不支持或提示独立转换，不用“支持 Word/Excel/PPT”笼统覆盖。Markdown 保留标题/行，PDF 保留页，DOCX 保留段落/表格定位而不伪造渲染页码，Excel 保留工作表和单元格范围，PPTX 保留幻灯片，图片只有实际得到坐标时才标区域，音频保留时间段。精确排版页码、嵌入对象、图表或旧格式需要各自验收。

库和计算路线先通过 Windows 原生样例验证，再选小而明确的实现；不预先承诺安装 Office、LibreOffice、Python 或远程服务。需要重算而当前路线不具备可靠能力时说明限制；若能根据原始数据直接计算，应展示方法与覆盖范围，不能假装已经执行原工作簿公式。

CLI/TUI/Web UI 都呈现实际使用的资料与未覆盖范围；Web UI 增加可跳转来源。Context 可以省略旧回合大块结果，但保留可重读引用与必要覆盖信息；压缩摘要不能作为全文阅读已完成的证据。

## 最小 Memory：独立于 RAG

未来在 `src/memory/` 中实现作用域、记录、修订、来源及 CRUD。用户“记住这个项目决定”本身就是明确指令，无需机械重复确认；含糊内容保持当前范围或询问，不自动提升为全局。只有明确的全局偏好跨项目，项目决定与约定不外溢，模型推断和 compact 摘要不自动成为长期事实。

每条 Memory 保留原始请求的 Session/回合或固定文件来源、用户指定内容、适用范围和修订；查看、修改与删除可以追溯。每次适用请求取最新有效记录，修正/删除使缓存失效；旧历史保留但不能把已失效 Memory 当作当前规则重新注入。验收覆盖恢复、fork 和 compact 后的失效记录，避免旧摘要重新激活删除内容。必须遵循的权限/工具规则仍由既有配置和代码落实，不能只靠 Memory 文本。

独立 Session 的既有私有 Memory 是否随迁入分享是尚待决定的产品问题；它与已确认的“上传资料转项目共享”不同。推荐默认仍绑定原 Session ID，仅该 Session 可以使用，其他项目 Session 不可读取；用户显式选择后才晋升为项目所有，避免把个人偏好一并共享。项目会话以后明确新增的项目决定按项目作用域保存。

首版用有界直接读取或简单筛选即可，不需要 Embedding。自动提炼、合并、冲突消解另作增量；以后可给 Memory 建派生索引，但不能与原件检索混成同一生命周期。

## 外部服务、模型能力与预算

| 边界 | 已确认方向 / 实施建议 | 实施前验证 |
| --- | --- | --- |
| 聊天模型 | 保留现有配置、SDK 和消息/工具关联约束 | 每个实际 API/模型的文本、图片、文件、音频能力；不能仅凭模型名字或 SDK 类型推断 |
| 视觉理解与文字提取 | 原生文本本地解析优先；图片/扫描页优先复用已验证的聊天多模态能力，不必先 OCR | 实际模型、API 与消息适配；页/图质量、文字覆盖、真实定位与 Windows 本地预处理 |
| 可选独立视觉/OCR | 当前能力不足或样例证明有收益时才接入，届时独立配置；未配置不阻塞可用路径 | 与现有模型比较识别质量、定位、成本及延迟；明确额外发送范围，不假定天然更优 |
| Embedding | 独立在线 API，与聊天/视觉配置分离 | 中文、精确术语、模型维度、批量上限及可观察用量 |
| 音频服务 | 独立配置转写/理解能力 | 时间定位、长片段切分、缺失与取消，不强制支持说话人识别 |
| 本地检索 | 关键词＋向量＋有界排序，索引可重建 | 代表性资料上的质量、更新/删除、中文切词和性能，再决定数据库、分块与排序 |

复用当前 SDK 的可兼容能力；若供应商协议确需新适配，记录原因并用假凭据与注入传输验收。本轮不写尚不可用的环境变量或默认参数，也不改锁文件。

每类外部请求要有每次/每文件/每回合的次数、批量、输入量、时限和输出限制，并接入取消、错误及用量记录。长任务呈现 pending/ready/partial/failed/cancelled 等真实状态；重试和备用识别消耗同一预算，不能隐式无限重试。API 不返回实际 token/费用时记为未知，不能伪造精确用量。未配置外部服务不能阻塞可本地完成的路径。

复用聊天模型时，视觉与转写辅助请求同样计入所属任务预算和用量，并约束图片字节、像素、页数与输出；不能把它们当作无预算的后台调用。相同凭据不等于可以扩大材料发送范围，所有请求只使用本次实际 Session 获准的资料与页面；不隐式改用其他供应商。独立服务只有实际接入时才增加配置，当前不添加不可用环境变量。

明确哪些内容离开本机：Embedding 接收待索引文本和查询，视觉接收选中的页/图片，转写接收音频片段，聊天接收被选择的证据或原生文件。“本地解析”不代表全程离线。凭据只来自运行配置，不进入 Session、Project、Memory、索引或日志；持久记录仅含非秘密的模型与版本元数据。

索引身份至少包括内容/解析版本、Embedding 提供方/模型/维度、分块配置和索引代次。配置变化使旧索引失效或分库重建，查询不能混用向量空间；供应商同名模型变化时也需要显式重建代次，不能假设维度相同就兼容。失败的索引任务不影响原件读取；精确关键词路径在向量不可用时仍可工作并说明降级。

多模态检索先比较文字提取、描述、转写的文本基线，再评估专用多模态 Embedding，复用既有范围与版本引用。文字提取可以由聊天多模态模型完成；文本 Embedding 本身不因此获得图片输入能力。专用图片/页面检索可不经过 OCR，但需要独立验证相应检索模型与查询契约，按代表性效果决定是否引入。语音入口复用相同 Session/Loop：只在输入完成边界提交一次，支持取消/打断/去重，未完成转写不能触发操作确认。
