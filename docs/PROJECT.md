# Fatcat 项目说明

Fatcat 是一个独立的 TypeScript Agent Harness，原生运行于 Windows，近期以本地编码任务为主要应用场景：读取项目、受控修改、执行验证并交付可审阅的结果。

本文维护稳定的项目目标与边界。使用与开发入口见 [文档首页](README.md)，总体结构见 [架构索引](ARCHITECTURE/README.md)；具体问题的方案、验收目标与未解决事项维护在对应专题，实施顺序由当前任务确定。

## 项目目标

- 建立可实际使用的本地开发闭环，让任务结果能够通过文件、命令和执行证据核对。
- CLI、可选 TUI 与本地 Web UI 共用 Session、Loop、模型通信、工具和权限边界。
- 由具体任务推动能力选择和演进。模型按需要选择通用工具、Skills 与有界委派，Harness 落实作用域、权限、预算和取消。
- 保持通用 Harness 的演进空间，以代表性任务的成功率与可维护性评价进展。

项目仍处于早期开发阶段。固定样例通过不能证明复杂任务已经成熟；实现、离线验证、真实环境验证和真实模型质量分别说明。版本以根 [package.json](../package.json) 为准。

当前只有开发者自用，优先清晰的当前设计，不默认建立历史会话或内部接口的兼容承诺。格式调整可以移除旧版本读取和迁移分支，并同步代码、测试与文档；不自动删除或改写已有文件。上线后再按实际用户需求明确支持范围、迁移方式和兼容期限。

## 核心原则

- **先交付可运行的增量。** 每次改动明确问题、范围与验收，保留已有用户行为和数据边界。
- **保持简单。** 以简单 Agent Loop 和少量通用、可组合工具为基础，抽象来自已经出现的需求。
- **明确职责与所有权。** 交互层处理输入和展示，Loop 控制回合，模型客户端负责通信，工具负责执行，Session 与各状态模块管理自己的数据。
- **以证据说明结果。** 工具成功、模型最终回答和任务验收是不同事实；失败、取消或中断后仍需准确报告已发生的操作。
- **优先正确性和任务质量。** 成本优化需要明确任务集合和成功率基线，不能以减少 token 代替任务完成。

## 工程边界

- 保持原生 Windows 和现有 TypeScript/Node.js 工具链。版本、包管理及 pi agent 风格要求统一由 [AGENTS.md](../AGENTS.md) 维护；具体依赖取舍见[架构总览](ARCHITECTURE/README.md)。
- 工具、Skills、委派、附件和 Memory 都不能自行扩大授权。权限模式中的明确例外及执行边界由对应架构定义；不把命令风险检查描述为 OS 沙箱。
- 保持持久历史、工作目录、资料作用域和执行事实的清晰边界。恢复历史不恢复旧授权，也不自动重放操作。
- 开发流程、语言要求、凭据保护和验证规范统一维护在 [AGENTS.md](../AGENTS.md)。

## 非目标与长期方向

当前不建设 Graph 引擎、无实际需求的扩展框架，或把参考项目整体迁入 Fatcat。Channel、App 和远程服务不是近期交付目标。已有能力的限制与可选后续设计由各架构专题维护；存在设计文档不代表已安排开发，恢复暂缓方向时须重新核对需求、代码和验收目标。

LoopX 的任务与证据管理、OpenViking 的上下文与记忆组织作为长期学习基准。采用何种机制，应在具体任务中核对参考版本、实现成本和可观察收益，不按功能数量追赶。
