# 检索、音频与后续资料能力（未实现方案）

[架构总览](README.md)

本文仅保留尚未实现、当前暂缓的方案与验收约束，不是交付排期。已有项目、原件、解析和 Memory 分别由 [Projects](PROJECTS.md)、[Attachments](ATTACHMENTS.md)、[Documents](DOCUMENTS.md)、[Memory](MEMORY.md)维护，不在此复制现状。

## 已确定的设计边界

- 附件分析不以向量化为前提。文本检索可复用现有解析，不必等待完整 Memory；Memory 也不依赖 RAG。
- 原件、解析/转写、检索索引、对话历史与 Memory 各自管理。索引是可重建派生数据，不能成为资料所有者。
- 模型按任务选择文件、页、查询和继续读取；Harness 落实实际 Session 作用域、能力、预算和取消，用户无需按任务启用内部检索开关。
- 全文总结/全面审查需要可核对的覆盖单位，不能用少量 top-k 命中冒充全文。预算不足、失败和未读范围必须明确。
- 视觉与文字提取优先复用当前已适配聊天模型；独立 OCR 只有在能力缺口或代表性样例证明收益时才接入，不预设必需服务。
- 在线 Embedding 与聊天模型独立配置；音频转写保留独立服务配置方向。未接入的服务不添加空环境变量或无效默认值。

## 文本检索方案

按原件版本取得可定位文本 → 生成带来源的分块 → 构建关键词/向量索引 → 在获准范围查询 → 展开完整章节、表格或页面核对 → 回答引用固定版本。直接读取路径在索引失败或未配置时仍可用。

索引身份至少包含内容/解析版本、Embedding 提供方/模型/维度、分块配置和索引代次。配置变化应失效或分库重建，不能混合不同向量空间；同名模型更新也要考虑显式重建代次，维度相同不代表兼容。

范围筛选与结果展开均需验证当前关联，不能只在 UI 隐藏跨项目结果。后台和子任务沿实际 Session/Project/归属代次执行；已知 ID、同目录或历史引用不授权。移除关联即时撤销查询/展开，保留字节的 pin 不恢复读取权。重建不能让旧引用指向新内容。

先建立精确关键词与文本基线，再用中文、专有术语、编号及跨文档任务选择分块、数据库、混合检索与排序。尚未选择库、Embedding 供应商或索引实现；不提前绑定大型框架。

## 多模态与音频方案

| 方向 | 选择条件 | 必须保留的证据 |
| --- | --- | --- |
| 可复用 OCR/视觉文字提取 | 当前模型不足，或专用服务在质量、定位、成本、延迟上有实际收益 | 原件/页/方法/模型版本、成功失败与未覆盖单位 |
| 原生文件输入 | 对实际 API 与模型验证支持后再适配 | 固定文件版本；只有文件级证据时不得编造页码 |
| 多模态检索 | 文本转写/描述基线不足，且专用检索表示经样例验证 | 文本、模型描述与原始视觉来源分开，报告跨模态遗漏 |
| 音频解析 | 按任务转写或理解选定片段 | 时间位置、失败片段、说话人不确定性与推断区别 |
| 语音入口 | 明确交互场景后复用现有 Session/Loop | 输入完成只提交一次，取消/打断/去重；未完成转写不能触发操作确认 |

图片描述不是完整原文；聊天模型支持图片不等于文本 Embedding 能直接索引图片。专用页面/图片检索可以采用不同于 OCR 文本的表示，但需要独立验证查询、来源与质量契约。未知坐标或置信度不能补造。

Excel 汇总仍需完整相关范围与可核对计算，不能只依赖片段召回或未验证公式缓存。旧 Office 是否需要转换支持、Office 渲染和公式重算采用何种路线，须单独决定，不默认要求 Office、LibreOffice、Python 或远程服务。

## 外部请求与数据边界

Embedding 会发送索引文本与查询，视觉发送选中图片/页，转写发送音频，聊天发送选择的证据。“本地解析”不意味着整条链路离线；相同凭据不能授权扩大材料范围，不隐式切换供应商。

每类请求需要次数、批量、输入/输出、每文件/回合、期限和取消上限；重试/备用路径消耗同一预算。未知用量记为未知，状态区分 pending、ready、partial、failed、cancelled。局部成功可保留带来源的产物，索引失败不能破坏原件读取。凭据不进入持久记录或日志。

## 恢复开发前的验收与待决问题

恢复某一方向时先重读当前实现并选择代表性任务。检查隔离、版本失效/重建、更新/删除、固定引用、取消、资源超限及外部请求范围；工程检查使用临时数据与注入传输，真实解析/OCR/转写/中文检索质量另用业务样例评估。

项目解除关联或跨项目迁移时，资料与 Memory 哪些可以带走仍需产品决定；当前没有这些操作。多模态模型、解析库、容量和排序策略以样例收益选择，不能从参考产品名称推断已具备能力。

保留的参考思想是：通用工具复用结构化内容、输入规范化与供应商转换分开、共享资料独立于聊天历史。它们是设计取舍，不是对其他项目当前实现或 Fatcat 性能的承诺。
