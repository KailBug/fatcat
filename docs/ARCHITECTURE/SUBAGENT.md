# Subagent：有界委派与独立历史

[架构总览](README.md)

委派用于自包含的小任务，默认可由模型按任务选择，不要求用户启用内部能力。它复用同一进程、Loop 和工具边界，不是线程池或多 Agent 调度框架。

## 装配与协议

`packages/runtime/src/subagent.ts` 为父 Tools 增加 delegate_task；`packages/runtime/src/agent.ts` 装配父子 Model 并添加任务选择指导。子工具集合不含 delegate_task，避免递归。

输入 task 是最多 4000 字符的非空任务说明。每次子任务从空历史开始，只带自己的任务和当前系统/目录/权限/Skill 元数据，不复制父消息或父已加载 Skill 正文。需要的材料由子任务重新读取，最终 answer 最多 12000 字符，超出则返回失败；子内部对话不并入父成功历史。

默认每父回合最多两个子任务，每个最多 min(父配置请求上限, 3) 次请求；顺序等待执行，不并行或自动重试。委派失败占用本次额度，父模型可依据安全错误继续判断。所有子任务共享父取消信号和基础工具 journal，不能扩大文件、网络、资料或命令权限。

## 执行身份与预算

父回合捕获的实际 Session/Project/归属代次绑定子任务，不从 UI 当前选中会话推断。目录级缓存不携带资料授权；附件与 Memory 读取通过执行绑定后的访问器校验。

父子使用同一供应商配置与完整请求字节规则，但子额度独立。子视觉/转写请求消耗自己的余额，并保留最终文字请求；子任务不能写 Memory 或管理父自动任务。全新子历史没有可省略的较早完整回合，超限不能靠丢弃当前结果规避。

父请求可见委派剩余额度和选择指导，只有父集合有委派工具。Skill 内容不能增加工具或预算。默认无条件分解任务会消耗额外调用，不是性能收益承诺。

## 事件与资料证据

子事件通过 subagent_event 携带身份与父子关系。共享 write/command/browser 记录可能在两层出现，消费者按 ID 去重；子 completed/stopped 不结束父回合。已观察的失败用量保留，缺失用量不填零。

成功委派可返回实际读取产生的 attachmentReads：最多 8 条、总计 8 KiB 来源元数据，每条最多 4 个来源链接，并报告省略数量。不复制正文，不从子答案中的口头声称生成证据。父历史可保留这些固定来源；失败子任务没有完整子历史或来源面板恢复，见 [Documents](DOCUMENTS.md)。

## 验证与未实现范围

检查独立上下文、父子定义分离、次数/输出限制、递归拒绝、权限继承、实际执行身份、共享日志、取消以及视觉余额。固定真实 DeepSeek 委派检查曾验证独立文件审查与无副作用边界；文件名和调用断言不能证明每条语义结论正确。

并行/递归委派、持久子会话、消息总线、共享工作记忆、自动任务分解和成本收益评估尚未实现。需要这些能力时先明确真实任务与验收，不扩展为通用框架。
