# Session：持久对话与会话管理

## 状态与范围

阶段 2A 的进程内 Session 与连续对话已通过离线、真实 DeepSeek 和 Windows 终端验证及用户 review。阶段 2D-14 按用户要求在 `feat/session-perfection` 增加本地持久化、新建、列表、命名、切换、继续最近会话和会话分支。实现与验证事实统一记录在 [PROGRESS.md](../PROGRESS.md)，不会以写入代码替代验证。

本轮参考 [Claude Code 官方会话文档](https://code.claude.com/docs/en/sessions)（2026-09-30 核对）的目录关联会话、继续/恢复、命名和分支定义，以及中断后先核查副作用的原则。Fatcat 按现有边界实现这些行为，不采用其内部存储格式，也不承诺功能等同。模型和权限继续由本次启动决定；未实现跨项目查找、文件检查点、回退、自动摘要、后台操作或工具重放。

## 模块与所有权

会话源码集中在 `src/session/`，与 `src/tools/`、`src/skill/` 同级；编译产物位于 `dist/src/session/`。Session、管理器、存储、历史校验和本地命令保留独立文件，交互入口直接导入对应模块，不增加 barrel、重新导出层或兼容旧路径的包装器。目录整理不改变会话协议、持久文件格式和运行行为。

| 模块 | 职责 |
| --- | --- |
| `src/session/session.ts` | 单个 Session 的成功模型历史、顺序执行和忙碌保护；在历史副本上调用 Loop，成功后才替换完整历史。 |
| `src/session/store.ts` | 规范工作目录对应的本地文件、版本与修订校验、历史校验、原子发布和跨进程更新冲突。 |
| `src/session/history.ts`、`src/session/commands.ts` | 文本历史与工具关联的恢复校验，以及 CLI / TUI 共用的本地命令和安全列表文本。 |
| `src/session/manager.ts` | 当前 Session 身份与持久状态；新建、列表、恢复、命名、分支及清空为新会话；处理最近未完成回合与恢复提示。 |
| `src/loop.ts` | 执行一个用户回合，调用模型和工具，返回答案与完整历史；向持久化边界提供已发生消息的检查点，不负责选择会话或文件位置。 |
| `src/agent.ts` | 按本次配置装配父子模型、Tools 和 Skills；不从会话文件恢复凭据或授权。 |
| `src/commands.ts` | chat / TUI 的共享本地命令分发；/skills 展示启动目录元数据，会话命令委托 session/commands，不请求模型或修改历史。 |
| `src/cli.ts`、`src/chat.ts`、`src/terminal.ts` | 入口选择、恢复参数、本地命令、终端提示与审批；chat 输入和单次确认由一个 readline 所有者隔离。 |
| `tui/` | 同一 SessionManager 上的终端交互、审批、显示与进程遥测。 |
| `webui/` | 同一 SessionManager 上的浏览器会话列表、操作与状态快照；HTTP 与审批边界不变。 |

Session、Manager、Store 分别回答“已成功完成的模型对话是什么”“当前在使用哪个会话”“如何可靠保存和读取”。Tools 保留进程内写入/命令事实，execution-report 汇总当前回合事件；这两类状态不归模型历史所有，也不会由恢复会话重新执行。

程序化 `new Session({ model, maxIterations, tools? })` 保持独立进程内会话入口。日常 CLI / TUI / Web UI 使用 `SessionManager.open(agent, { workspace, store?, selection?, persistence? })`，通过 `run()` 执行当前会话；管理方法为异步 `list()`、`newSession()`、`resume()`、`rename()`、`fork()` 和 `reset()`。`current` 是身份摘要，`history` 是完整历史副本，`persistent` 表示是否使用磁盘。选择条件包含 continue、resume、fork 和 name。

同一个 Manager 同时只允许一个活动回合。运行中不切换、不新建、不清空、不重命名或分支；错误明确返回，不排队或隐式合并操作。恢复失败保持原活动会话。不同持久会话历史相互独立；分支复制原会话的完整已完成历史并获得新 ID，后续更新写到分支，原会话保留。

## 本地存储

默认根目录为 Node 用户主目录下的 `.fatcat/sessions`；`FATCAT_SESSION_DIR` 可覆盖根目录。每个规范工作目录使用 SHA-256 子目录，目录内每个 Session 使用 UUID 命名的 JSON 快照。工作目录按实际 realpath 规范化；历史恢复限当前工作目录，不通过名称跳到其他目录。`--workspace` 与启动目录规则沿用原入口，存储不会扩大 read/write/shell 范围。

快照保存格式版本、Session ID、名称、时间、工作目录、修订号、完整成功历史和最近未完成回合。后者含 prompt、startedAt、updatedAt、status、code、已产生 messages 和 ownerPid。API 凭据、环境变量、模型客户端、工具权限、审批答复及进程遥测不写入快照。历史包括用户提示、模型答案、工具参数与结果、读取的文件/网页和完整已加载 Skill；采用本地明文 JSON，不加密或自动清理。

每个快照最多 64 MiB，先检查文件大小再读取和解析；不将模型请求字节预算当作磁盘或历史内存上限。读取检查格式、版本、身份、工作目录、修订号、文本消息与工具关联。成功历史只能由完整用户回合构成；工具结果必须与所在 assistant 批次关联，未完成或孤立调用不能混入成功历史；调用 ID 在同一用户回合不能重复，跨成功回合可复用。恢复时使用当前 systemPrompt，避免旧 system 指令替代当前程序规则。

更新在短时跨进程锁内核对预期修订号，写临时文件并原子发布；旧实例不能覆盖其他进程已经提交的新版本。活动回合保存 ownerPid，其他进程不能把仍在执行的会话当作已中断历史恢复。确认 ownerPid 已退出后通过独占恢复门重新检查并清理陈旧事务锁，避免两个恢复者删除彼此的新锁。不完整 `store.lock` 或恢复进程崩溃留下的 `store.lock.recovery` 保守报忙，提示确认没有存储操作后再人工移除；不按超时猜测并删除活动锁。磁盘故障作为会话错误呈现；不会假称未确认保存的答案已经持久化。此边界解决正常多进程误覆盖，不提供抵御恶意本机进程的 OS 隔离。

## 回合与中断边界

成功历史 → 保存本轮开始记录 → Loop 在历史副本上执行 → assistant / tool 消息更新未完成记录 → 获得最终答案 → 原子提交完整成功历史并清除本轮未完成状态。

开始记录必须在模型或工具执行前完成；无法写盘就不开始外部工作。失败、取消或迭代耗尽保留此前完整成功历史，另外保存本轮已经产生的消息与停止原因。未完成数据不会作为合法 tool 对话拼入下一次请求；恢复先向用户显示中断提示，下一次模型请求附加有界恢复说明，要求核查当前文件与操作效果，恢复本身不发起请求。发现已退出进程留下的 running 状态也采用此边界，不自动恢复模型请求、继续审批或重跑工具。仅保留最近一次未完成回合，下次成功提交后清除；这不是永久失败审计日志。

完整历史在入口、成功出口和对外读取时复制，避免模型、请求投影或 UI 的可变引用篡改已保存数据。恢复或分支后的下一次请求仍通过同一 Context 和模型预算边界；快照永远保存完整正文，`context_omitted` 只是当前请求的投影。

副作用与历史提交不是同一个事务。文件修改、shell 命令、已发送给模型的数据和已发生费用不会因为模型失败、取消、切换、新建或保存失败撤销。跨进程只恢复对话与未完成回合提醒，Tools 的实时 journals 和进程累计 token 不恢复；旧成功 tool 内容也不是当前文件或新测试通过的证据。

Manager 暂存根 Loop 的 completed / stopped，待持久化成功或停止处理后才向观察器发出一次终止事件；子任务事件照旧透传。成功回答但最终写盘失败时报告 stopped / SESSION_STORAGE，并保留已观察用量与副作用，不把纯模型完成误报成已保存会话。开始记录失败也会以零模型请求的 stopped 报告结束。程序化普通 Session / Loop 保持原事件时机；回调抛错或强制终止不保证最终报告，发布成功后的回调异常不能撤销已保存历史。

## 入口与会话命令

正常任务、`--chat`、`--tui` 默认新建持久会话；`--webui` 默认进入未保存的空白草稿，首次提交才保存。继续已有对话需要显式选择。`--continue` / `-c` 使用当前工作目录最近会话，`--resume` / `-r` 按 ID 或名称恢复，`--name` / `-n` 命名，`--fork-session` 在恢复后创建独立分支。`/sessions` 在 chat / TUI 内本地列表，命令不调用模型，但交互启动仍要求正常 provider 配置；bare `--resume` 保留无需凭据的终端选择/管道列表路径。`--no-session-persistence` 使用临时进程内历史。具体参数互斥和交互命令见 [USAGE.md](../USAGE.md)。

chat 与 TUI 的 `/new`、`/clear`、`/reset` 开始新会话并保留原会话，`/sessions` 列表，`/resume` 切换，`/rename` 命名，`/fork` 分支。未知斜杠命令只提示，不发给模型。新建不撤销操作或清除工具事实；同一进程切换会话仍保持启动时的 workspace、provider、Skills 与权限。

Web UI 各标签共享一个 Manager 和活动会话。入口设置 `deferEmptySessions: true`：未命名的新 Session 只在 Manager 内持有 revision 0 的草稿，不进入 Store 或内存列表。New chat 和删除活动会话也进入此状态，前端不把草稿补进侧栏。首次 `run()` 沿用原开始记录保存，在模型/工具执行前取得持久修订；失败和中断保留记录。显式命名和分支仍立即保存，空草稿的显式分支不引用不存在的源快照。CLI / TUI 默认未启用此选项，存储格式不变。旧空快照不会自动清理。

侧栏选择已有会话，命名与分支调用相同管理器；刷新从服务状态重新连接。浏览器关闭不取消回合，终端 Ctrl+C 停止服务和当前模型/审批。界面显示记录、报告和模型历史仍是不同状态；重启恢复对话不等于恢复全部旧活动和遥测。细节见 [WEBUI.md](WEBUI.md)。

同阶段 Web UI 右键菜单补充按所点 ID 命名、分支和删除。命名/删除未活动会话不切换当前历史；所点会话分支成功后打开新分支。删除在当前规范工作目录内通过 Store 锁核对预期修订，拒绝仍在运行的会话；Web UI 删除活动会话成功后才切换到未保存的草稿，删除失败保留当前历史。未启用延迟创建的 Manager 仍使用原持久空会话替代行为。会话删除只清除其持久快照，不撤销文件/命令，不清除 Tools journals，不自动删除子分支。CLI / TUI 的现有命令范围不随 Web UI 菜单增加删除命令。

## Skills、Context 与执行事实

Skills 目录在启动时发现，元数据只加入请求指导，不属于保存历史。通过通用 read 加载的 `kind: skill` 完整正文属于关联工具结果：成功回合随完整历史持久保存，失败回合仅在未完成记录保留。它不参与旧 read 省略；普通引用页仍可能按 file/directory/search 条件在请求副本中省略。恢复会话不会自动重读已加载指令或热刷新目录，子任务仍有独立空历史。

每个用户回合重置迭代计数和委派额度，调用 ID 按回合检查。执行报告只根据本轮实际事件汇总写入、命令、模型用量与请求投影；原始成功历史中的工具输出不能算作本轮新执行。Tools 每个实例最多保留 100 次写入暂存尝试和 20 次命令启动尝试，进程退出后丢失；新建或切换会话不清除这些事实或上限。

请求仍可能因全部用户/assistant 消息、Skill 正文、当前/最近回合和执行事实超出字节预算。`MODEL_CONTEXT_LIMIT` 不发送该请求，不丢弃已完成历史；新建会话也不保证进程执行事实一定能放入预算。没有自动摘要、历史淘汰或内存硬上限，详见 [CONTEXT.md](CONTEXT.md)。

## 验收与限制

验收覆盖真实临时目录中的跨实例保存/恢复、新建保留、列表、名称、分支独立、工具关联、非法/损坏/超大数据、原子写入失败、取消、中断记录、并发和修订冲突，以及 CLI / TUI / Web UI 的共有行为。自动模型检查使用虚构凭据与注入传输；Windows 终端、浏览器和真实模型验证分别在 PROGRESS 中记录，不能用旧阶段 API 验收证明本轮持久化已在线验证。

恢复仅限当前规范工作目录。没有 Claude Code transcript 导入、跨项目全局搜索、Git worktree 自动关联、文件检查点、撤销、自动工具重放、恢复后台任务、跨进程审批、自动摘要、导出菜单、保留期管理或远程同步。存储内容可能含项目与对话私密数据；使用 `--no-session-persistence` 可关闭本次保存。会话文件是内部版本化格式，当前不承诺外部应用的稳定导入协议。
