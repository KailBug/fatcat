# Agent Loop：设计与实现安排

## 当前边界

本轮交付供 review 的工程准备部分：构建命令、CLI 入口和本地配置校验。模型请求、内存历史、工具执行和循环控制尚未实现，不构成第一阶段完整验收。

## 已实现模块

| 模块 | 当前职责与接口 |
| --- | --- |
| `src/cli.ts` | 接收进程参数；无参数或 `--help` / `-h` 显示帮助；`--check-config` 执行本地配置检查；设置退出码 |
| `src/config.ts` | `loadConfig(env = process.env): Config` 返回 `apiKey`、`model`、`maxIterations`；非法值抛出不包含配置原值的错误 |
| `tests/config.test.ts` | 使用 Node 内置测试运行器检查默认值、覆盖值、缺失配置、非法迭代上限和错误信息 |

当前数据流：CLI 参数 → 帮助，或环境变量 → 配置校验 → 安全摘要 / 错误提示 → 退出。没有网络请求，也没有工具调用。

退出码：`0` 表示帮助或本地检查成功；`1` 表示配置错误；`2` 表示不支持的参数或任务输入。配置检查成功不代表凭据有效或第一阶段闭环已通过。

配置使用 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL` 和 `HARNESS_MAX_ITERATIONS`。默认模型为 `deepseek-flash`，默认最大迭代次数为 `8`。配置中的密钥只供后续客户端使用，不输出完整配置对象。未设置的可选字段采用默认值，显式空值视为错误。

## 模型接入方案（计划，未实现）

- 用户已指定 DeepSeek。首版计划使用其官方地址 `https://api.deepseek.com` 和 Chat Completions 协议。
- 参考 [DeepSeek 官方 Node.js 示例](https://api-docs.deepseek.com/)，计划在接入时使用 `openai` SDK 作为兼容客户端；本轮没有安装 SDK，也没有建立客户端或适配框架。
- 默认模型名来自 2026-09-18 核对的官方文档，可通过 `DEEPSEEK_MODEL` 修改；可用性仍需真实请求验证。
- 先完成非流式调用；思考模式与工具调用历史的具体处理，在实现时按当时的 DeepSeek 官方协议确认并记录，不预先冻结消息接口。

## 循环与工具边界（计划，未实现）

模型调用负责提交消息与工具定义、解析响应。循环控制负责内存历史、工具结果关联、终止判断和迭代计数。工具执行负责参数校验和一个无副作用的示例工具。

最大迭代次数按模型请求轮次计数；每轮请求前检查上限，无工具调用且得到最终回答时结束，否则执行工具并回传关联结果。当前只实现了上限配置校验，尚未实现循环限制。

具体文件、消息类型、示例工具与错误恢复策略，在相应步骤实施时确定，不提前添加空接口。

## 实现安排

1. **工程准备（本轮 review 范围）**：建立 Windows 原生工具链、配置和 CLI 入口；验证编译、本地校验与错误退出。
2. **单模型响应（计划）**：接收任务输入、配置 DeepSeek 客户端，完成一次请求和最终输出；落实超时、模型错误与必要日志。
3. **工具闭环（计划）**：加入内存历史、无副作用工具和最大迭代限制，保留工具调用与结果的关联，完成连续交互。
4. **阶段验收（计划）**：自动化验证循环边界与错误路径；真实 DeepSeek 请求验证直接回答与工具闭环，更新 Windows 操作步骤。

详细验证结果与阻塞统一记录在 [PROGRESS.md](../PROGRESS.md)。本轮结束后留待用户 review，再继续后续实现。
