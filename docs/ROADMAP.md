## 第一阶段验收边界

- 按 [USAGE.md](USAGE.md) 的步骤，能够在 Windows 原生环境安装、配置并运行 CLI。
- 输入无需工具的问题，模型直接给出最终结果，程序正常结束。
- 输入适合示例工具的问题，模型提出工具调用；参数经过校验，调用和结果正确关联，结果回传后模型继续生成最终回答。
- 单次运行的消息历史足以支持上述循环，不依赖持久 Session。
- 对缺失配置、非法工具参数、工具执行错误和模型调用失败给出可理解的错误结果或提示，不无限循环。
- 达到最大迭代次数时明确终止；日志能确认迭代、工具调用和结束原因，不泄露密钥。
- 在 PROGRESS.md 记录验证方式和结果；使用模拟模型的检查不能替代真实模型闭环验收。缺少凭据等条件时如实记录未验证部分，不宣称阶段完成。

第一阶段不包含 Graph、持久 Session、完整插件系统、Subagent、多渠道、长期记忆、检查点恢复、复杂调度和 UI。

## 阶段 2A：内存 Session 与连续对话（已完成）

解决单次 CLI 结束后无法继续追问的问题。范围（已实现、验证并通过用户 review）：

- 保留已有单次任务命令，新增显式 `--chat` 连续对话入口。
- Session 在进程内保存成功回合的完整消息；每个回合继续复用现有 Loop。
- 提供 `/help`、`/reset`、`/exit`，支持输入结束和 Ctrl+C 退出。
- 失败或取消的回合丢弃本轮临时历史；同一 Session 不接受并发执行或执行中重置。
- 每个用户回合独立计算模型迭代上限，日志可区分各回合。

验收条件：离线验证连续追问、工具历史关联、会话隔离、清空、失败后继续、取消、并发拒绝，以及 CLI 命令与退出码；真实 DeepSeek 验证至少一次依赖前文的追问。已有单次任务与工具闭环必须继续可用。

不加入磁盘持久化、历史压缩、恢复、插件、Subagent 或 Channel；不预先细化阶段 2 的其余子系统。具体系统设计见 [Session 文档](ARCHITECTURE/SESSION.md)。

## 阶段 2B：最小 Tools 与只读工作目录（已完成）

本节记录当时已验收的增量；原工具名称已在阶段 2D-1 合并为 read，当前协议见 TOOLS.md。

解决 Agent 无法使用本地文本回答问题的限制。范围（已实现、验证并通过用户 review）：

- 将工具定义、参数校验和异步执行统一到一个工具集合，模型和 Loop 使用同一实例。
- 保留默认 sum；仅在用户显式传入 `--workspace <directory>` 时添加 `list_directory` 和 `read_file`，单次任务及连续对话均可使用。
- 限制读取在指定目录内，拒绝越界、链接路径和隐藏路径，限制文件大小与目录返回条数；结果和错误按工具调用 ID 回传。
- 文件内容只作为数据；保留现有取消、迭代上限、失败回合隔离及不记录内容的日志行为。

验收：离线验证工具定义与执行一致、Windows 路径边界、隐藏文件与链接拒绝、内容和数量上限、异步取消，以及 CLI/Session 闭环；真实 DeepSeek 只对专用虚构样例验证目录查看和读取后的回答。

不加入写文件、shell、通用插件加载、权限审批框架或其他子系统。系统实现安排见 [TOOLS.md](ARCHITECTURE/TOOLS.md)。

## 阶段 2C：最小 Subagent（已完成）

本节记录阶段 2C 当时的验收；默认可用迁移见 2D-4。

当时范围（已实现、验证并通过用户 review）：通过显式 `--subagent` 为父 Agent 增加 delegate_task 工具，委派一个自包含小任务；子 Agent 使用独立内存历史、同一 DeepSeek 配置与原有只读工具，完成后返回答案，父 Agent 再继续回答。

每个父用户回合最多启动 2 个子任务，各最多 3 次模型请求（也不超过配置的迭代上限）；顺序执行，子 Agent 不具有委派工具。只返回最终答案或安全错误，不合并子任务内部历史。父取消信号传到子任务；日志关联父调用 ID。

验收：离线验证历史隔离、结果关联、独立回合预算、递归阻止、次数/迭代上限、错误回传、取消与工作目录继承；真实 DeepSeek 完成委派、子工具调用、父回答闭环。具体系统安排见 [SUBAGENT.md](ARCHITECTURE/SUBAGENT.md)。

## 阶段 2D：本地开发闭环（进行中）

目标：让 Fatcat 完成一个真实本地代码修改任务并运行验证，不以新增子系统数量衡量进展。

- 采用少量通用入口，以 read、write、shell 表达职责；2D-6 将字面文本搜索放入 read 的可选 query，不增加专用搜索入口。write 应支持可 review 的精确修改，不能只靠盲目覆盖文件。
- 命令执行遵守 Windows 原生约束，建议默认 PowerShell；shell 为暂定名称，Bash 不作为安装前提。
- 权限、输出边界、超时、取消及执行事实记录随读写和命令能力一起落实。失败回合不能让已经发生的写入在任务记录中消失。
- 委派能力转为正常可用，由 Agent 判断是否调用；Harness 保留预算和权限约束，子任务不能扩大父任务权限。2D-4 已移除 --subagent 开关并完成默认可用迁移。
- 根据任务需要完善 Session、Context 和 Task，不要求本阶段建成完整持久化、记忆或恢复平台。

验收方向：在固定本地样例项目上定位问题、做出预期修改、运行明确的检查并报告结果；验证失败、权限拒绝和取消均能准确结束或继续，不误报完成，不盲目重复有副作用的操作。单独记录离线与真实模型结果。子任务选择也需验证简单任务可直接完成、适合委派的任务可在预算内委派。

2D-1 先实现通用读取与目录定位，随后逐步加入受控修改和验证；固定临时样例已完成读改验证闭环；任务驱动委派迁移已在 2D-4 验证，更广泛任务验收与回答证据一致性仍待完善。

## 阶段 2D-1：通用 read 工具（已完成并通过 review）

本轮已将 list_directory / read_file 合并为一个 read 入口，保留显式工作目录授权和现有路径边界。支持稳定排序的非递归目录分页、按行读取及明确的继续位置。单次文件输入与工具输出均有上限；拒绝非法分页参数，不能将截断内容误报为完整结果。

内部拆分路径解析与访问检查、读取协议与分页，不增加依赖，不加入写入、shell、搜索引擎或新子系统。旧工具名称在本次迁移后移除。Subagent 默认可用的迁移留待后续增量，不改变当前开关。

验收已通过：目录跨页无遗漏或重复（目录不变时），文本分页保留换行和行位置，空文件/尾页/超长行/大文件有明确行为，既有路径与取消边界保持；SDK、Session、CLI 和子任务都使用同一新定义；真实模型完成分页读取并给出正确结果。

## 阶段 2D-2：受控 write（原功能与交互修正均已合入）

在 feat/workspace-write 上已实现通用 write：新建文件或唯一文本片段替换，后续 review 修正默认 CLI 权限为 ask：终端逐次 yes/no 确认，不要求重启授权；显式 read-only 和 workspace-write 分别用于强制只读和脚本预授权。read / write 在指定目录后都可被模型选择，权限在执行处强制校验。

保留路径、扩展名、编码和大小边界；已有文件修改不匹配或片段不唯一时拒绝，提交前复查内容变化。写入记录独立于成功对话历史，模型失败或取消不抹去已发生的文件变化；记录包含摘要信息，不包含文件正文。记录只在进程内保留，并输出必要事件，不承诺崩溃恢复。

验收已通过：创建防覆盖、精确替换与冲突、权限及路径拒绝、取消/模型失败后的事实可见、父子相同权限及 Windows 原生文件操作。离线测试包含发布结果不确定和发布成功后清理失败；真实模型对专用临时样例完成创建、读取、精确修改和再次读取。记录最多 100 次已进入暂存阶段的尝试，不自动丢弃；/reset 不清除写入事实或回滚文件。本次 review 修正另验证了终端确认与聊天输入隔离、拒绝/EOF/取消、确认期间文件变化，以及 You> 亮绿色提示。该修正使用离线模拟模型和真实 Windows 伪终端验证，没有重新请求真实 DeepSeek。暂不加入 shell、递归建目录、删除文件、持久化或新的委派模式。

## 阶段 2D-3：Windows shell 与命令验证（已通过 review 并合入）

新增一个 shell 入口，默认 Windows PowerShell；用户不必开启工具功能，选定工作目录后即可由模型选择。命令默认逐次终端确认，授权与写权限分离，显式只读拒绝 shell。启动目录不是系统沙箱，确认界面必须说明命令可访问当前用户权限内的文件和网络。

本轮已落实参数与 cwd 校验、非交互进程、退出码、输出上限、超时、取消与进程树终止，以及独立于成功历史的命令事实；复用父子权限和输入确认边界。不加入后台任务、长期运行服务、调度或默认委派迁移。

验收已通过：Windows 原生命令成功/非零退出、拒绝/取消、输出超限终止、超时、进程清理及失败回合后的记录；真实 DeepSeek 在固定临时样例完成读文件、精确修改、运行测试和报告结果。每次 shell 最多 16 KiB 原始输出，超时默认 30 秒、最多 120 秒；每个工具实例最多保留 20 次命令尝试，输出摘要每流最多 1000 Unicode 码点。验收事实见 PROGRESS。正常父进程退出并不保证所有脱离的后代进程已退出，后台执行不在本轮范围。

## 阶段 2D-4：任务驱动委派（已通过 review 并合入）

CLI 的父 Agent 默认具有 delegate_task，由模型判断任务是否值得拆分；移除 --subagent 参数。简单回答、单次计算或直接文件操作应直接完成，独立调查/审查可以委派；这种选择由父模型请求中的指导和工具说明共同引导，不是固定分类器或成功率保证。

保留最多两次子任务、各最多 min(3, 配置上限) 次请求、顺序执行、独立历史、相同权限与记录、取消传播及禁止递归。把实际 CLI 的父子模型装配集中在一个小函数中，供离线和真实验证复用。不建设新框架。

验收已通过：116 项离线测试覆盖原有行为及默认 CLI 委派、SDK 父子定义与关联、权限继承和请求指导不污染历史；原有预算和取消回归通过。真实模型在最终固定场景中直接完成算术，并用两个子任务完成要求隔离审查上下文的任务。短文件审查可能直接完成，不保证所有独立审查都会委派，也未证明最优拆分或成本改善。失败检查、调整原因和请求次数见 PROGRESS.md。

## 阶段 2D-5：回合执行报告（已通过 review 并合入）

由程序根据实际事件汇总每个用户回合的请求次数、工具返回、写入及命令结果；CLI 单次任务与聊天默认输出，模型失败或取消仍保留报告。父子共享的记录去重，命令后又有 write 尝试时明确标记。回答完成、工具 ok、命令正常退出均不直接等同于任务验收通过。

验收已通过：126 项离线测试覆盖原有回归及未执行命令、失败、取消、非零退出、超时/截断结果汇总、子任务去重、回合及 reset 隔离；真实固定编码样例使用 4 次请求完成读取、修改和命令检查，执行报告与工具记录匹配，独立复验通过。报告不解析或保证每条自然语言声明，也不监控 shell 或外部进程导致的文件变化。不添加新的工具或完整 Task/证据关卡系统。

## 阶段 2D-6：read 文本搜索（已通过 review 并合入）

在现有 read 增加可选 query，对单文件或选定子树做区分大小写的字面搜索，返回相对路径、原始行号与匹配行。匹配行按路径、行号稳定分页；父子 Agent 使用同一能力，用户无需开启功能或授权命令。

复用路径、扩展名和有界 UTF-8 读取；限定原始目录条目、候选文件、递归深度和结果字节。资源超限明确报错并要求缩小范围；候选文件过大或编码不支持时记录跳过数量与 complete=false，分页结束不等于覆盖完整。没有正则、索引、Git ignore 解析或文件快照。

验收已通过：137 项离线测试包含递归定位、行号、大小写与字面匹配、分页/超限/取消、路径边界、CLI 和子任务继承；真实 DeepSeek 在临时多文件样例中使用搜索定位后读取、修改指定源文件并运行固定测试。初始失败、受保护文件未变、独立复验和执行报告均经脚本核对。此样例不证明大仓库覆盖、通用成功率或 token 成本改善。

## 阶段 2D-7：请求容量与用量记录（已通过 review 并合入）

本节记录 2D-7 当时的验收；请求侧旧读取省略见 2D-8。先补齐历史和工具结果累积时的可见边界：对父子模型完整 JSON 请求体检查可配置字节预算，超限不发送、不自动裁剪消息；回合报告分开统计请求大小和服务返回的有效 token 用量。缺失或非法统计保持未知，失败前的已收到用量与执行事实仍可见。

验收已通过：151 项离线测试覆盖字节/转义/工具定义计量、精确边界、无网络超限、有效/未知用量、截断/失败/取消、父子隔离、写入后超限、Session 历史保留与 reset 边界、CLI 和安全日志。真实临时多文件编码样例完成搜索、读改测与独立复验，逐次请求字节和有效用量可核对；详情见 PROGRESS。

不加入 token 估算器、自动摘要、历史淘汰、持久日志或金额上限。请求字节上限不限制进程历史内存，不保证服务端上下文一定能容纳，也不证明成功率或成本改善；阶段 2D 整体继续按实际任务完善。

## 阶段 2D-8：旧读取结果的请求投影（已验证并合入）

针对连续对话累积读取内容后触及预算的情况，在模型请求副本上按最旧优先替换成功 read 结果，使用明确的 context_omitted 标记；文件、目录和搜索结果均可处理，替换不能反而增加大小。请求未超预算时保持原样，达到预算就停止整理。

保护当前回合、最近完成回合、所有用户要求及 assistant 消息、调用参数和 ID、错误、其他工具结果、写入与命令事实。Session 仍保存完整历史；模型按需重新读取，重读仍使用原权限及工具边界。整理后仍超限就保持 MODEL_CONTEXT_LIMIT，不调用额外模型或隐藏重试。

验收已通过：161 项离线测试覆盖原有回归及请求正文、精确字节、工具关联、不可变历史、当前/最近回合保护、失败/reset、跨回合文件变化后的重读及 CLI 元数据。真实三回合只读临时样例在第三回合触发整理，模型重读后报告更新内容，保留上一回合格式要求；既有真实多文件编码验证也通过。具体次数与结果见 PROGRESS.md。

在 `feat/webui-dev` 修正启动、重复 New chat 和活动删除自动增加空记录的问题。共享 Manager 提供未命名新会话的内存草稿，首次提交在模型/工具执行前保存；侧栏不展示未保存草稿，显式命名、分支和恢复仍可用。保留既有空快照、CLI/TUI 默认语义、存储格式及修订/忙碌保护。验收涵盖重启、刷新、活动/未活动删除、首次保存失败、失败回合记录与后续提交，事实见 PROGRESS；不扩展为自动清理或自动续聊。

### 同阶段补充：页面弹窗、自动打开与上下文显示

按用户要求在 `feat/webui-dev` 将命名、分支和删除统一为页面内居中弹窗，启动本地服务后自动打开私有链接。composer 以最近父请求输入 token / 所选模型窗口替换 Workspace context 标签，并将模型移至工作区右侧；未知用量或未知窗口明确标注，保留原请求字节预算。界面英文，多语言切换为后续计划，本轮不实现。

验收涵盖取消/键盘/输入校验/重复提交、活动与未活动目标、冲突与忙碌保护、浏览器打开失败回退及正常退出、实际用量与未知状态、父子请求隔离、切换/恢复后的观测清除，以及宽窄屏和深浅色。自动模型与操作系统打开器使用注入检查，实际模型效果另记；不增加后台任务、模型切换、tokenizer 或状态持久格式。

### 同阶段补充：权限模式与 composer 选择

在 `feat/webui-dev` 按现有工具能力提供 Manual、Accept edits、Plan：逐项审批、受控写入自动允许、只读规划。后续同增量按用户要求新增 Free to go：开放当前用户权限内本地文件和 HTTP(S) 地址范围，普通命令自动，明显危险及不透明命令审批。`src/permissions/` 与 session 同级集中模式、审批、命令风险判断及路径/文本/进程/网络 guard，交互展示和具体工具操作维持原职责。CLI / chat / TUI 可在启动选择，Web UI 空闲切换同一父子策略；显式 launch read-only/shell-deny/web-deny 为上限，恢复会话不恢复授权，原模式和旧 allow 参数保留原范围。

composer 采用消息输入和底部工具栏：左侧权限/带框工作区，右侧无框上下文/模型/发送，窄屏按组换行；会话副信息移至悬浮提示。四项菜单按 Plan、Manual、Accept edits、Free to go 展示，采用英文和键盘导航。验收覆盖真实临时工作区外/隐藏/链接文件、局域网 DNS 注入与本机 HTTP 服务、普通命令自动和危险命令拒绝/审批、切回原范围、父子共享、忙碌与断连、取消与旧 ID、启动选项/上限、原 CLI/TUI/Web 回归及宽窄深浅主题。风险命令测试使用注入执行器，浏览器有额外固定命令限制；不实际执行删除等指令。检查是启发式，不扩大为模型 Auto 审查、完整规则列表、OS 沙箱或自动计划执行；结果和脚本/hook 限制见 PROGRESS。
