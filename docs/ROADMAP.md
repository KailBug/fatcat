本路线图保留粗粒度阶段，不是详细排期。第一阶段边界已确定；后续阶段的拆分和顺序可根据真实需求调整，进入阶段前再细化。实际完成情况以 [PROGRESS.md](PROGRESS.md) 为准。

## 第一阶段验收边界

- 按 README 的步骤，能够在 Windows 原生环境安装、配置并运行 CLI。
- 输入无需工具的问题，模型直接给出最终结果，程序正常结束。
- 输入适合示例工具的问题，模型提出工具调用；参数经过校验，调用和结果正确关联，结果回传后模型继续生成最终回答。
- 单次运行的消息历史足以支持上述循环，不依赖持久 Session。
- 对缺失配置、非法工具参数、工具执行错误和模型调用失败给出可理解的错误结果或提示，不无限循环。
- 达到最大迭代次数时明确终止；日志能确认迭代、工具调用和结束原因，不泄露密钥。
- 在 PROGRESS.md 记录验证方式和结果；使用模拟模型的检查不能替代真实模型闭环验收。缺少凭据等条件时如实记录未验证部分，不宣称阶段完成。

第一阶段不包含 Graph、持久 Session、完整插件系统、Subagent、多渠道、长期记忆、检查点恢复、复杂调度和 UI。

## 阶段推进方式

当前阶段先交付，再回顾结果并确定下一阶段的最小范围。进入下一阶段前补充具体任务和验收方式，不提前冻结远期接口、依赖或排期。必要日志和基本错误处理从第一阶段开始，后续阶段是在已有能力上完善。
